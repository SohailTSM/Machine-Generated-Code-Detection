## 1. Project Overview

This project builds a **Graph Neural Network (GNN)** to detect whether source code was written by a human or generated by an LLM. It's built for the [SemEval-2026 Task 13](https://huggingface.co/datasets/sohailtsm/my-semeval-dataset) competition.

**Three subtasks:**

| Task | Problem | Classes | Dataset Size |
|------|---------|---------|-------------|
| A | Binary Detection (human vs machine) | 2 | ~50K train, ~10K val |
| B | Authorship Attribution (which LLM?) | 11 | ~58K train, ~11K val |
| C | Hybrid Detection (human/machine/hybrid/adversarial) | 4 | ~900K (local) |

**Competition metric:** Macro F1-Score.

**How it works (high level):**
```
Source Code → Tree-Sitter AST → Graph (nodes + 4 edge types)
                                   ↓
                           + CodeBERT embeddings (semantic)
                           + TF-IDF features (lexical)
                                   ↓
                    SemanticGraphTransformer (GNN)
                                   ↓
                          Classification → Submission CSV
```

## 6. Pipeline Walkthrough (Step-by-Step)

Here's exactly what happens when you run `python run.py --task A`:

### Step 1: Configuration (`config.py`)
- Reads `ENV` and `ACTIVE_TASK`
- Sets device (MPS/CUDA/CPU), batch size, paths
- Creates output directories (`pt_chunks/`, `checkpoints/`, `submissions/`, `logs/`)

### Step 2: Load Data (`data_loader.py`)
- Loads `train.parquet` and `validation.parquet` from local or HuggingFace (`sohailtsm/my-semeval-dataset`)
- For **Task A**: remaps the 11-class training labels → binary (0=human, 1=machine) if needed
- Drops rows with empty/null code or labels
- In DEBUG mode: stratified subsample to 500 train + 100 val

### Step 3: Initialize Parsers (`tree_sitter_utils.py`)
- Creates tree-sitter parsers for 8 languages: Python, C++, Java, JavaScript, Go, C#, C, PHP
- Parsers convert raw code strings into Abstract Syntax Trees (ASTs)

### Step 4: Build Vocabulary (`vocab.py`)
- BFS traversal of all training ASTs
- Collects unique node type names (e.g., `function_definition`, `if_statement`, `identifier`)
- Maps each type → integer ID (max 8000 types)
- Cached as JSON (reuses cache on re-runs if `GRAPH_LOGIC_VERSION` hasn't changed)

### Step 5: CodeBERT Embeddings (`codebert_embedder.py`)
- Loads frozen `microsoft/codebert-base` model (~500MB)
- For each AST node's source text, computes a 768-dim CLS embedding
- **Deduplication:** Thousands of nodes share the same text (e.g., `if`, `return`) — only unique texts are embedded, then looked up by text
- Results saved to disk as `.npy` files (one-time cost, reuses cache on re-runs)
- After precomputing, the CodeBERT model is **unloaded from memory** to free RAM/VRAM

### Step 6: TF-IDF Features (`tfidf_extractor.py`)
- Fits a TF-IDF vectorizer on all training code strings
- Extracts 100-dim feature vector per code sample
- Captures lexical style patterns (variable naming, operator frequency, etc.)
- Saved to disk for reuse

### Step 7: Build Graph Dataset (`dataset.py`)
- For each code sample:
  1. Parse code → AST via tree-sitter
  2. Convert AST → graph with 4 edge types (parent→child, child→parent, sibling, next-token)
  3. Extract 6 structural features per node (depth, position, children count, etc.)
  4. Attach CodeBERT embeddings and TF-IDF vector
  5. Create a PyG `Data` object
- **Streaming augmentation** (training only): 15% of samples get an augmented copy (identifier renaming, whitespace changes, dummy comments)
- Graphs are saved in chunks of 5000 to disk (`.pt` files)
- On re-runs, cached chunks are loaded directly (fast)

### Step 8: Model Initialization (`model.py`)
- Creates the `SemanticGraphTransformer` (v9_scaled, ~33.7M params):
  - Node type embedding (512-dim)
  - Structural features (6-dim)
  - CodeBERT projection (768→512)
  - 6 TransformerConv layers (1024-dim, 16 heads) with residual connections
  - JumpingKnowledge aggregation (max)
  - GlobalAttention pooling
  - TF-IDF fusion → MLP classifier (1124→1024→512→C)

### Step 9: Training (`training.py`)
- **Loss:** FocalLoss with class weights + label smoothing
- **Optimizer:** Adam (lr=5e-4, weight_decay=1e-4)
- **Scheduler:** OneCycleLR with 30% warmup (steps per optimizer step, not per batch)
- **Gradient Accumulation:** 2 steps (effective batch = batch_size × 2)
- **AMP:** Mixed precision on both MPS and CUDA (GradScaler on CUDA only)
- **Early stopping:** Saves best model by val macro F1, stops after 10 epochs without improvement
- **Logging:** Per-epoch loss, F1, balanced accuracy printed to console (+ WandB if configured)

### Step 10: Evaluation & Visualization (`visualization.py`)
- After training: loads best checkpoint
- Generates:
  - Training curves (loss + F1 over epochs)
  - Confusion matrix heatmap
  - Per-class F1 bar chart
  - Full classification report (precision, recall, F1 per class)

### Step 11: Test Sample Evaluation
- Loads `test_sample.parquet` (labeled test data, 1K samples)
- Builds graphs, runs evaluation with metrics
- Prints Macro F1, Balanced Accuracy, Loss, and full classification report
- Useful for comparing model performance on held-out test data

### Step 12: Inference on Final Test Files (`inference.py`)
- Loads test parquet from `final_test_files/test_task{X}.parquet` (500K rows, no labels)
- Builds graphs for test samples
- Runs model prediction
- Saves submission CSV with columns `id, prediction` to `submissions/`

- Skip WandB
- Run on MPS (Mac) or CPU
- Complete in ~5-10 minutes per task
- Create output in `checkpoints/`, `logs/`, `pt_chunks/`

```bash

python run.py --task A --env local --no-wandb

# Full training on Task B
python run.py --task B --env local --no-wandb

```

### With WandB experiment tracking

```bash

python run.py --task A --env local
```

### On Kaggle

```bash
python run.py --task A --env kaggle
```

### Resume training (after interruption or across Kaggle accounts)

```bash
# Resume from the auto-saved resume checkpoint
python run.py --task A --env kaggle --resume

# Resume from a specific checkpoint file
python run.py --task A --env kaggle --resume-from "/path/to/resume_taskA.pt"
```

**Cross-account workflow:**
1. Training runs on Kaggle Account 1 — gets interrupted or compute runs out
2. Download `checkpoints/resume_taskA.pt` from the Kaggle output
3. Upload it as a Kaggle dataset on Account 2
4. Run with `--resume-from "/kaggle/input/<dataset-name>/resume_taskA.pt"`

### Inference only (after training)

```bash
# Uses the best checkpoint from training
python run.py --task A --env local --inference-only

# Or specify a specific checkpoint
python run.py --task A --env local --inference-only --checkpoint "checkpoints/best_model_taskA.pt"
```

## 8. What Happens Under the Hood

### Caching system

The pipeline caches aggressively so re-runs are fast:

| What | Where | Invalidated when |
|------|-------|-----------------|
| Raw data parquets | `task_a/`, `task_b/`, `task_c/` | Never (manual download) |
| Node vocabulary | `pt_chunks/global_vocab_*.json` | `GRAPH_LOGIC_VERSION` changes |
| CodeBERT embeddings | `pt_chunks/*.npy` + `.json` | Data changes or cache deleted |
| TF-IDF model | `pt_chunks/tfidf_model_task{A,B,C}.joblib` | Deleted or DEBUG mode |
| Graph chunks | `pt_chunks/task_a_train_<hash>/` | Config hash changes |
| Model checkpoints | `checkpoints/best_model_task*.pt` | Every training run (best val F1) |
| Resume checkpoints | `checkpoints/resume_task*.pt` | Every epoch (full training state) |

**First run** will be slow (CodeBERT embeddings + graph building). **Subsequent runs** with the same config will skip straight to training.

To force a full rebuild, delete the `pt_chunks/` directory:
```bash
rm -rf pt_chunks/
```

### Memory management

- CodeBERT is loaded → used → unloaded before training starts
- Graph chunks use LRU caching (only 2 chunks in RAM at once)
- Mixed precision reduces memory by ~40%
- On Mac: `num_workers=0` avoids MPS multiprocessing issues

### Model architecture (~33.7M parameters)

```
Input per node:
  - Type embedding:     [N, 512]   (learned, from 8000-word vocab)
  - Structural features: [N, 6]     (depth, position, children, etc.)
  - CodeBERT projection: [N, 512]   (768→512 linear)
  → Concatenated:        [N, 1030]
  → Projected:           [N, 1024]

Graph processing:
  → 6× TransformerConv layers (1024-dim, 16 attention heads, edge-aware)
  → JumpingKnowledge (max over all layers)
  → GlobalAttention pooling → [B, 1024]

Classification:
  → Concat TF-IDF [B, 100] → [B, 1124]
  → MLP: 1124 → 1024 → 512 → NUM_CLASSES
```

## 10. Troubleshooting

### "ModuleNotFoundError: No module named 'torch_geometric'"

```bash
pip install torch_geometric
```

### "ModuleNotFoundError: No module named 'tree_sitter_python'" (or other languages)

```bash
pip install tree-sitter-python tree-sitter-cpp tree-sitter-java tree-sitter-javascript tree-sitter-go tree-sitter-c-sharp tree-sitter-c tree-sitter-php
```

### "FileNotFoundError: Test file not found"

You need test data for `--inference-only` mode. Place it at:
```
task_a/task_a_test.parquet
```

### "RuntimeError: MPS backend out of memory"

Reduce batch size in `src/config.py`:
```python
"local": {
    "batch_size": 8,   # reduce from 16
    ...
}
```

### "CUDA out of memory" (on Kaggle)

Reduce batch size:
```python
"kaggle": {
    "batch_size": 256,  # reduce from 512
    ...
}
```

### Training seems stuck / F1 equals baseline

If `VaF1 ≈ Baseline` (e.g., 0.5 for Task A), the model has collapsed to always predicting one class. Try:
1. Reduce learning rate: `LEARNING_RATE = 1e-4`
2. Check data loading: are labels actually balanced?
3. Re-run with `--debug` to test on small data first

### Cancel training and use the model anyway

You can safely Ctrl+C or stop a Kaggle notebook mid-training. After at least 1 completed epoch:
- `checkpoints/best_model_task{X}.pt` has the best model seen so far → use with `--inference-only`
- `checkpoints/resume_task{X}.pt` has the full training state → use with `--resume` to continue later

```bash
# Use the interrupted model for inference
python run.py --task A --env kaggle --inference-only

# Or resume training later
python run.py --task A --env kaggle --resume
```

### Want a fresh start (delete all caches)

```bash
rm -rf pt_chunks/ checkpoints/ logs/ submissions/
```

### Console output format during training

```
Ep 01 | TrLoss=0.6312 TrF1=0.6543 | VaLoss=0.5890 VaF1=0.7123 | Baseline=0.5000 | LR=1.20e-04 | 45.2s ★ saved
Ep 02 | TrLoss=0.5101 TrF1=0.7234 | VaLoss=0.4890 VaF1=0.7456 | Baseline=0.5000 | LR=1.80e-04 | 43.1s ★ saved
...
⏹ Early stopping at epoch 15 (patience=10)
✓ Loaded best checkpoint (val F1 = 0.8234)
```

- **TrLoss/TrF1:** Training loss and macro F1
- **VaLoss/VaF1:** Validation loss and macro F1
- **Baseline:** Majority-class F1 (if VaF1 ≈ Baseline, model collapsed)
- **★ saved:** Best model checkpoint was updated this epoch
- **⏹:** Early stopping triggered
